Architectural Pattern: Actor-Critic (Quality Gate) vs. Supervisor

Supervisor Pattern (Task Routing)

A central "Supervisor" agent delegates different sub-tasks to specialized domain workers (e.g. web_researcher, nl2sql, rag) and combines their results. Used when solving multi-step tool-use problems.

Actor-Critic / Quality Gate (Our Architecture)

A dual-agent self-correcting loop where one agent drafts content (Generator) and an independent, unbiased agent audits it against hard pass/fail criteria (Evaluator). On failure, targeted feedback forces self-correction. Exactly matches the assessment goal: an agent that judges its own quality before shipping.

Orchestration

The orchestration is managed by LangGraph using a typed state graph (AgentState). Conditional edges make retry bounds and branching declarative rather than an error-prone imperative loop.

node_evaluate_content

Independent Evaluator Agent judges the lesson against the 10 rubric checks using temperature=0.0 and returns structured Pydantic JSON (EvaluationResult).

Deterministic temp=0.0 Pydantic v2
5

_decide_after_evaluation (Edge)

Conditional edge: If passed=True, routes to finalize. If passed=False and retry_count < max_retries, routes to regenerate. Otherwise, terminates.

Conditional Edge Bounded Loop

Constructs a targeted prompt containing exact failure reasons, specific required fixes, and previous draft. Logs the rejection to SQLite and triggers rewrite.

Targeted Feedback Rejection Logging
7

Compiles final lesson content, builds complete rejection audit log, records execution outcome into SQLite run_history, and transitions state to complete.

🛠️ Technology Stack & Architectural Rationale

🕸️

LangGraph 1.x

Role: Cyclic Workflow Orchestration

Provides explicit typed state transitions (AgentState TypedDict), declarative conditional retry edges, and guarantees strict termination without hidden global state or infinite loops.

🤖

Google Gemini 3.5 Flash Lite

Role: Core Large Language Model (gemini-3.5-flash-lite)

Selected for high reasoning performance, rapid inference speed, and cost efficiency across multi-call agentic loops. Generator runs with temperature=0.2; Evaluator runs with temperature=0.0.

📦

FAISS + Google Embeddings

Role: Grounded Knowledge Vector Store (models/gemini-embedding-001)

Zero cloud database dependencies. Chunks verified domain references (600 chars, 100 overlap) and caches FAISS index locally to disk with staleness detection based on file modification timestamps (ref_mtime).

⚖️

Independent Evaluator Agent

Role: Strict Quality Gate

Operates in complete isolation from the Generator's internal system prompts. Eliminates confirmation bias and returns structured, schema-validated JSON outputs via Pydantic.

💾

SQLite Self-Evolving Memory

Role: Cross-Run Failure Learning

Stores historical failure patterns in output/memory.db. Increments frequency counts on recurring mistakes and injects past pitfalls into future generator prompts to prevent repeat errors.

⚡

FastAPI + Non-Blocking Polling

Role: Backend API & Client UX

Incoming generation requests spawn background worker threads and return an immediate run_id. Vanilla JS polls GET /runs/{run_id} every 2 seconds, providing smooth live progress updates.

📊 The 10 Hard PASS/FAIL Evaluation Checkpoints

Strict: No Partial Credit

To eliminate subjectivity, the Evaluator judges every lesson against 10 strict boolean checks. If any single check fails, the entire lesson is marked FAIL and rejected for regeneration.

# Criterion Name Target Dimension Verification Rule
1 accuracy Technical Correctness Ensures no materially incorrect technical claims (e.g., catches false retraining claims).
2 grounding Factual Consistency All factual claims must be consistent with retrieved reference documentation.
3 beginner_friendly Target Learner Fit Language suitable for 12th-grade Indian graduate with limited English vocabulary.
4 jargon_explained Clarity All technical terms (embeddings, vector database, retrieval) defined with simple analogies.
5 why_rag Core Motivation Clearly explains the problems RAG solves (outdated knowledge & LLM hallucinations).
6 rag_workflow Process Mechanics Correctly outlines the complete 4-step pipeline: Query → Retrieve → Augment → Generate.
7 example Teaches by Example Must include at least one concrete, relatable real-world scenario (e.g., support bot).
8 key_concept_coverage Curriculum Completeness Must explicitly cover: Knowledge Base, Embeddings, Vector DB, Retrieval, Context, Generation.
9 coherent_teaching_flow Pedagogical Structure Logical progression from simple foundational intuition to technical mechanics without jumping.
10 standalone Self-Sufficiency Learner grasps the core concept completely without needing external search or help.

🧠 Self-Evolving Feedback Loop (How Memory Works)

The platform satisfies the Self-Evolving requirement across runs by recording failure patterns in SQLite:

1. Failure Capture

On any evaluation failure, save_evaluation_failures() writes the check name, failure reason, and actionable correction to the memory_feedback table.

2. Recurrence Weighting

If the same check fails repeatedly on future runs, SQLite increments the frequency counter and updates last_seen.

3. Prompt Sharpening

At the start of subsequent runs, load_memory_feedback() fetches high-frequency pitfalls and injects them directly into the Generator prompt.

🎬 Built-In Demo Mode (Deliberate Error Walkthrough)

To enable reliable demonstration during Loom recording without manual code hacks, the UI includes a Demo Mode toggle:

  • Step 1: Demo Mode injects a deliberate fallacy into the Attempt 1 prompt: "RAG retrains the language model whenever a new document is uploaded."
  • Step 2: The Evaluator Agent inspects the lesson and immediately fails the accuracy checkpoint.
  • Step 3: Attempt 1 is recorded in the Rejection Log with the exact reason and correction instructions.
  • Step 4: LangGraph invokes node_regenerate_content, which passes the failure details into the rewrite prompt.
  • Step 5: Attempt 2 is generated with the error corrected, passes all 10 checks (10/10 PASS), and is shipped with the full rejection audit trail.
